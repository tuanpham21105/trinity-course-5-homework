    ✏️ Files: src/entities/item.entity.ts, a new migration, src/common/dto/page-query.dto.ts, src/game.module.ts, src/game.service.ts, src/game.controller.ts, src/main.ts

    Migration = versioned SQL. Seed = rows inserted by a migration. Pagination = LIMIT + OFFSET, never the whole table.

    Expected result

    GET /items?page=1&limit=4 → 200 { "data": [4 items], "page": 1, "limit": 4, "total": 8 } GET /items?page=2&limit=4 → the next 4 items GET /items → page 1, limit 10 (all 8 items) GET /items?page=1&limit=1000 → 400 (or limit capped at 20) Item = { "id": 1, "name": "Wooden Dagger", "icon": "🗡️", "attack": 1, "price": 15 }

    Seed data (use these exact rows)

    1 Wooden Dagger 🗡️ attack 1 price 15 2 Iron Sword ⚔️ attack 3 price 40 3 Hunter Bow 🏹 attack 4 price 60 4 Battle Axe 🪓 attack 5 price 75 5 War Hammer 🔨 attack 8 price 130 6 Magic Wand 🪄 attack 12 price 200 7 Sea Trident 🔱 attack 18 price 320 8 Dragon Blade 🔥 attack 30 price 600

    Hints

    • Item entity: id (primary generated), name, icon, attack (int), price (int).
    • Migration: generate CreateItem, open the new file, add the 8 INSERT INTO "item" ... rows at the end of up(), then run it.
    • PageQueryDto: page default 1, limit default 10 with @Max(20). Query values are strings, so use @Type(() => Number).
    • Service: findAndCount({ order: { id: 'ASC' }, skip: (page - 1) * limit, take: limit }).
    • main.ts: turn on new ValidationPipe({ transform: true }).
    • Module: add TypeOrmModule.forFeature([Item]).

        Goal: each click hits the monster and saves the new state.

        ✏️ Files: src/game.service.ts, src/game.controller.ts

        Load → change → save. The request has no body. Never trust the client with gold or damage.

        Game rules

        • damage = the player's attack (1 for now).
        • Monster HP goes down, never below 0.
        • At 0 HP: gold + (5 + kills × 2), xp + 25, kills + 1, monsterHp = null.

        Expected result

        POST /players/:id/attack (no body) → 200/201 { "damage": 1, "defeated": false, "reward": null, "player": Player } → 8th hit on a Slime: "defeated": true, "reward": { "gold": 5, "xp": 25 } → 404 if the player does not exist The next GET /players/:id must show the new gold.

        Hints

        • Reuse the monster helper from Step 2: hp = monsterHp ?? maxHpFor(kills).
        • After changing the player, call save(player). Returning the object is not enough.
        • @Post('players/:id/attack') with @Param('id', ParseIntPipe).
        💡 Stuck?
        • Gold is right in the response but wrong in the next GET? You forgot to save().
        • Slime has 8 HP. The 8th hit must kill it.

Damage in attack() uses it too.

          Hints
